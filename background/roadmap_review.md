Disposition note: this plan isn't consolidating prior findings — it's pivoting strategy on the strength of a research overview, so the review asks a different question than usual: **does this plan follow from the evidence, and does it preserve the discipline that produced the evidence?** Verdict: **the destination is right, the route is inverted.** The generalization is real and defensible — but this plan proposes to *freeze a generalized interface before a single instantiation has run*, re-opens three separate frozen artifacts without records, and draws one new component whose pipeline description quietly duplicates Solvent's authority role. Findings:

## Critical

**C1 — The "Trust Verifier" as drawn is either the Coordinator misnamed or a second epistemic authority.** §4's pipeline: evidence → provenance validation → claim construction → obligation evaluation → consistency checks → **promotion gate** → **authorization decision** → consequential intent. The last three stages are Solvent's — the promotion gate is *database-enforced in the kernel*; authorization is the frozen authority boundary. If the verifier "runs" these, Solvent becomes a ceremonial store and the verifier is the shadow-authority problem — the exact failure the lineage polices, now at architecture level. The diagram compounds it: DOMAIN PACK → TRUST VERIFIER → SOLVENT/CONDUCTOR places a reasoning-adjacent component *above* the authority boundary. The fix is renaming and re-locating, not redesign: **the generalized verifier is the domain-adapter + coordinator layer** (mechanical validation, compilation, challenge orchestration — the deterministic Go component you already specified); it *prepares* transitions; **the gate stays in Solvent, period.** §4's pipeline should terminate at "propose gated transition" — everything after is kernel.

**C2 — This plan violates the project's own newest rule: interfaces are extracted from working instantiations, not authored in advance.** The pivot document's central lesson was *stop proving by argument, start proving by execution*. Since then: Workflow Design v1.0 froze (never executed), the research POC froze — packet schema, coordinator, two-role agents (never executed), Plan 11.1 was approved (not yet executed). This plan now generalizes to Domain Packs **from zero completed instantiations** — "BM-IST becomes the first Domain Pack" means the pack interface is speculative until BM-IST has run *as BM-IST*. The debt-vocabulary decoupling — which §3 correctly cites as the template — succeeded precisely because it generalized from a *working* implementation after repository inspection. Same rule, next level: **run the EBP research POC as a concrete system first; extract the Domain Pack interface from the seams that actually hurt.** Every interface designed today will be revised after the first run; authoring it now is the analysis-paralysis pattern in generalization form. Sequence: Plan 11.1 → research POC (as itself, not as "Pack #1") → interface extraction → then the pack abstraction with evidence behind it.

**C3 — The eight primitives re-open the schema decision the two-ledger architecture just closed.** Claim/Evidence/Provenance/Obligation map cleanly onto the frozen Solvent schema (belief/evidence/debt/provenance-class). But **State, Authorization, and Consequence** as primitives are incoherent across the boundary: state exists in *both* ledgers (epistemic vs. operational — the distinction §12/§13 of the plan elsewhere insists on), authorization is Solvent's alone, consequence spans intent (Solvent) and effect (Executor/SOR). Presenting an eight-primitive abstract model invites implementing a third store or a unified one — the exact collapse risk. The generalized model must be a **reading of the two existing ledgers plus the coordinator's translation role**, not a new ontology. Deliverable shape: a mapping table (primitive → owning ledger → kernel enforcement), not a schema.

## High

**H1 — "Promotion rules" in the Domain Pack (§3) is ambiguous at exactly the load-bearing point.** If domain packs define promotion rules, either the rules compile to the kernel's existing structural gate (which obligations attach, which discharge them — the debt-decoupling pattern), or Solvent's gate becomes configurable — a kernel change requiring a Growth Gate. The precedent says the former; the plan must say so in one sentence: *domain packs own obligation attachment and discharge semantics; the gate itself (empty-debt + no-final-truth) is invariant kernel structure.*

**H2 — Challenge engines (§8) must be declarative or they resurrect the Reasoning Agent.** "Domain packs supply falsifiers, contradiction tests, acceptance criteria" — as *data* (test references, checker artifacts, vocabulary), executed by transient agents and validated mechanically, this is consistent with the frozen two-role design. As *executable components* in the loop, it's agent reasoning reintroduced with a new name, minus two revisions of mutation gates. Specify the form.

**H3 — The human gate map didn't survive the generalization.** §3 lists "consequential actions" as Domain Pack configuration — but the frozen protocol established that specific transitions are *structurally* human-gated (faithfulness, promotion, final-truth), not domain-configurable. If a pack can define consequential actions with arbitrary gating, the generalization erases the gate map. The invariant: **which transitions *may* be consequential is domain vocabulary; which consequential transitions require a human is structural.**

**H4 — Attestation P0 (§7) is correct for production and wrongly sequenced for now.** Producer identity, signing, trusted timestamps: all real gaps, all correctly identified. But the research POC has zero external consequences and its integrity is covered by the corpus manifest + hashes. Stacking four new infrastructure concerns before first run re-imports the pre-pivot pattern (building for the imagined deployment). Right sequence: attestation becomes P0 *gated on first external-consequential use*, not on first internal use. Same for the interoperability adapters (§10): W3C PROV/OTel export with zero consumers is speculative surface — record the intent in the decision record, build when the first integration partner exists.

**H5 — The freeze-ledger is now in open violation.** Three frozen artifacts are implicitly amended by this plan (Workflow Design v1.0's scope, the research POC architecture, BM-IST's status as validation target), plus Plan 11.1 sits unexecuted while strategy moves again. The decision-record discipline — violated at every pivot and every time retroactively justified — needs a single **strategy-level record**: what freezes remain binding (Solvent kernel, Workflow Design v1.0 for the POC), what is superseded, what is deferred-not-dead. Without it, "frozen" has stopped meaning anything, and the discipline that licensed the kernel contraction dies with it.

## Medium

The verifier's "auditable state transitions" need a named ledger (Solvent status/refusal_log + Conductor activity — say which records what). §12's non-goals should gain the C1/H2 corollaries: no verifier-side adjudication, no executable challenge engines as agent reasoning. Domain Pack count discipline: the pack interface ships with *exactly one* conformant pack (EBP/BM-IST) and a conformance test — resist designing for imaginary second domains; the floor taxonomy (guidance doc) is the correct form for that.

## What survives

The core claim is right and now has external backing: the defensible abstraction is the provenance-aware epistemic authority ledger; the four-plane separation is the invariant; the debt-decoupling is the correct generalization template; BM-IST-as-validation-not-architecture restores the original framing; the non-goals list is exactly right. Nothing here needs to be *rethought* — it needs to be *resequenced and re-homed*.
